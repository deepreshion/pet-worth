# Native E2E

Требуются Maestro, запущенный симулятор/эмулятор, установленный development build, Metro и локальный Supabase с Inbucket. Production-аккаунты и реальные медицинские данные не использовать. Деморежима нет.

1. `npm run supabase:start`; перенести локальный publishable key в `.env`.
2. Для iOS использовать `EXPO_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321`, для Android Emulator — `http://10.0.2.2:54321`. Перезапустить Metro после изменения `.env`.
3. `npm run ios` или `npm run android`. Закрыть onboarding development client.
4. `E2E_PLATFORM=ios npm run e2e:smoke` или `E2E_PLATFORM=android npm run e2e:smoke`.

Runner создаёт отдельный email для каждого прогона, запрашивает OTP через настоящий экран входа, читает 6-значный код из локального mailbox и вводит его в приложении через Maestro. Код передаётся только процессу локального теста через `E2E_OTP` и очищается после проверки; Maestro может включать тестовый ввод в свои локальные отчёты. Используются только одноразовые локальные тестовые аккаунты. Проверка URL запрещает запуск с облачным Supabase. Metro должен быть запущен с тем же локальным URL, что и runner.

В `supabase/config.toml` настроены оба шаблона OTP (`magic_link`, `confirmation`), длина 6 цифр и интервал повторной отправки 60 секунд. Если локальный стек уже работал до изменения config, перезапустите его без сброса базы. Уникальные тестовые пользователи и питомцы остаются в локальной базе до её сброса.

Автоматический smoke охватывает вход, создание/редактирование питомца и перезапуск. Вложения, календарь и системные разрешения проверяются по матрице в `docs/migration-verification.md`; автоматический smoke не заменяет полную приёмку.
