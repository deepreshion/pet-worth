# Pet Worth: дизайн-кит

Статус: **Черновик для согласования**  
Версия: **0.1**

Этот документ описывает визуальную систему Pet Worth до проектирования финальных экранов. Его задача: согласовать характер бренда, цвет, типографику, форму компонентов, иллюстрации, движение и правила доступности.

## 1. Дизайн-концепция

### Короткое определение

**Спокойная забота, а не больничный интерфейс.**

Pet Worth хранит важные медицинские данные, поэтому интерфейс должен быть точным, предсказуемым и хорошо читаемым. При этом продукт остаётся личным: фотография питомца, мягкие формы и редкие отсылки к Сене снимают тревожность и не дают приложению выглядеть как кабинет клиники.

### Для кого проектируем

- Для владельцев кошек и собак без медицинской подготовки.
- Для семьи, где несколько людей участвуют в уходе.
- Для ситуации, когда информацию нужно быстро показать врачу.
- Для регулярного, но не ежедневного использования.

### Характер бренда

| Качество | Как выражается |
|---|---|
| Спокойный | Низкий визуальный шум, ясная иерархия, короткие тексты |
| Заботливый | Реальные фотографии питомцев, мягкая геометрия, человеческий язык |
| Надёжный | Контраст, точные даты, явные статусы, понятные ошибки |
| Живой | Один яркий цвет действия, характер Сени в редких деталях |
| Ненавязчивый | Нет геймификации здоровья, бесконечной анимации и декоративных метрик |

### Дизайн-параметры

- `DESIGN_VARIANCE: 6/10` - узнаваемая композиция без визуального хаоса.
- `MOTION_INTENSITY: 3/10` - только обратная связь и переходы состояния.
- `VISUAL_DENSITY: 5/10` - достаточно данных для ухода, но без ощущения панели управления.

### Принцип приоритета

На каждом экране должен быть один главный вопрос:

- Главная: что требует внимания сейчас?
- Питомец: что важно знать о нём?
- История: что происходило и когда?
- Событие: что было сделано и какие документы приложены?
- Клиники: куда можно обратиться?

Если блок не помогает ответить на главный вопрос экрана, он переносится глубже или удаляется.

## 2. Основа системы

### Технологическая база

Используем существующий Ionic Vue как единственную компонентную основу. Не смешиваем его с Material, Fluent, Carbon или другими дизайн-системами.

### Поведенческая база

- На iOS сохраняем знакомое поведение навигации, свайпов и системных листов.
- На Android сохраняем ожидаемое поведение кнопки назад и системных диалогов.
- Собственный характер создаём токенами, типографикой, фотографиями и композицией, а не заменой нативных паттернов.

## 3. Цветовая система

### Основная идея

База нейтральная и прохладная. Яркие цвета имеют постоянные роли. На одном экране используется один доминирующий акцент, остальные цвета работают только как семантические или поддерживающие.

### Правила использования

1. Главная кнопка использует лаймовый фон и тёмный текст.
2. Голубой отвечает за бренд и крупные фоновые области, а не за каждую ссылку.
3. Коралловый не заменяет красный цвет ошибки.
4. Сиреневый используется для документов и справочных блоков, но не как универсальная заливка.
5. Статус всегда передаётся цветом, иконкой и текстом одновременно.
6. Чистые `#000000` и `#FFFFFF` не используются как фон всей страницы.

## 4. Типографика

### Основной шрифт

**Manrope Variable** для всего интерфейса.

Почему:

- поддерживает кириллицу;
- хорошо читается в небольших размерах;
- сочетает мягкую геометрию с нейтральным характером;
- одна variable-семья уменьшает визуальную и техническую сложность.

Шрифт нужно хранить локально в приложении. Рекомендуемые насыщенности: `400`, `500`, `600`, `700`, `800`.

Источник для подключения: [Manrope в репозитории Google Fonts](https://github.com/google/fonts/tree/main/ofl/manrope). Эта сборка содержит улучшенную кириллицу и распространяется по OFL.

Fallback:

```css
font-family: "Manrope", "SF Pro Text", "Segoe UI", system-ui, sans-serif;
```

### Типографическая шкала

| Стиль | Размер / строка | Вес | Применение |
|---|---:|---:|---|
| Display | `40 / 44` | 800 | Имя питомца, ключевой момент экрана |
| H1 | `32 / 38` | 800 | Заголовок страницы |
| H2 | `24 / 30` | 700 | Основной раздел |
| H3 | `18 / 24` | 700 | Карточка или группа |
| Body | `16 / 24` | 500 | Основной текст |
| Body strong | `16 / 24` | 700 | Важное значение |
| Small | `14 / 20` | 500 | Вторичная информация |
| Caption | `12 / 16` | 600 | Подпись, дата, вспомогательный статус |

### Правила типографики

- Один шрифт на весь продукт.
- Максимум три веса на одном экране.
- Не использовать весь текст прописными буквами.
- Даты, время, вес и дозировки получают `font-variant-numeric: tabular-nums`.
- Цвет вторичного текста должен проходить WCAG AA.
- Имя питомца может быть крупным, но не вытесняет ближайшее действие из первого экрана.

## 5. Сетка и расстояния

### Базовая единица

Сетка строится на шаге `4 px`.

Шкала расстояний:

| Токен | Значение |
|---|---:|
| `space.1` | `4 px` |
| `space.2` | `8 px` |
| `space.3` | `12 px` |
| `space.4` | `16 px` |
| `space.5` | `20 px` |
| `space.6` | `24 px` |
| `space.8` | `32 px` |
| `space.10` | `40 px` |
| `space.12` | `48 px` |

### Мобильный каркас

- Боковое поле: `16 px`, на широких телефонах `20 px`.
- Расстояние между крупными разделами: `32 px`.
- Расстояние внутри карточки: `16-20 px`.
- Минимальная зона нажатия: `44 x 44 px`, целевая: `48 x 48 px`.
- Нижняя навигация учитывает safe area.
- Контент не должен скрываться под фиксированной навигацией.

## 6. Форма и поверхность

### Радиусы

Используем мягкую, но не игрушечную систему:

| Токен | Значение | Применение |
|---|---:|---|
| `radius.control` | `12 px` | Поля, чекбоксы, небольшие кнопки |
| `radius.card` | `20 px` | Обычные карточки и уведомления |
| `radius.feature` | `28 px` | Фото питомца, главный блок экрана |
| `radius.pill` | `999 px` | Основная кнопка, фильтр, статус |

### Границы и тени

- Обычная карточка отделяется либо границей, либо тенью, но не обоими эффектами одновременно.
- Базовая граница: `1 px color.line`.
- Тень используется только для плавающей навигации, листов и модальных окон.
- Тени получают оттенок фонового цвета, без чистого чёрного.

## 7. Иконки

Используем только **Ionicons**, так как они уже входят в Ionic и покрывают системные сценарии продукта.

Правила:

- Контурная версия для обычного состояния.
- Заполненная версия только для выбранного пункта навигации.
- Основные размеры: `20`, `24`, `28 px`.
- Иконка без текстовой подписи допустима только для общеизвестного действия и при наличии accessibility label.
- Эмодзи не заменяют продуктовые иконки.
- Нельзя смешивать Ionicons с другим набором на одном экране.

## 8. Фотографии и образ Сени

### Фотографии питомцев

- Реальные пользовательские фотографии являются главным эмоциональным материалом.
- Кадрирование держит глаза и морду в безопасной центральной зоне.
- Предпочтительны естественный свет и домашняя среда.
- Фото не затемняется без функциональной причины.
- Текст поверх фото требует стабильной подложки или градиентного scrim.

### Маскот

Сеня задаёт характер бренда, но не становится навигатором или медицинским советчиком.

Допустимо:

- логотип и splash screen;
- пустое состояние;
- onboarding;
- редкая декоративная деталь в навигации;
- иллюстрация успешного завершения настройки.

Не допускается:

- маскот рядом с каждым событием;
- шутки в сообщениях об ошибках и здоровье;
- маскот, который даёт медицинские рекомендации;
- несколько разных стилей изображения Сени на одном экране.

Лимит: не более одной заметной отсылки к Сене на экран.

## 9. Компоненты

### Кнопки

**Primary**

- Лаймовый фон, тёмный текст.
- Высота `52 px`.
- Полная ширина в ключевых мобильных сценариях.
- Один primary action на экран.

**Secondary**

- Прозрачный или нейтральный фон.
- Граница `1 px color.line`.
- Текст `color.ink`.

**Danger**

- Красный текст на нейтральном фоне по умолчанию.
- Сплошная красная заливка только в подтверждении необратимого действия.

**Icon button**

- Размер `44-48 px`.
- Обязательный accessibility label.
- Активное состояние: `scale(.98)` или смещение на `1 px`.

### Поля формы

- Label всегда находится над полем.
- Placeholder содержит пример, но не заменяет label.
- Высота поля не менее `52 px`.
- Helper text располагается под полем.
- Ошибка располагается под полем и содержит способ исправления.
- Focus ring не зависит только от изменения цвета границы.

### Карточка питомца

Содержит:

- фотографию;
- имя;
- вид и возраст;
- один полезный статус или ближайшее действие;
- явную возможность открыть профиль.

Не содержит отдельную кнопку «Сменить питомца». Несколько питомцев переключаются свайпом с фиксацией карточки.

### Карточка события

Порядок информации:

1. Тип события.
2. Название.
3. Дата и время.
4. Начало заметки, если она есть.
5. Индикатор вложений.
6. Индикатор напоминания, если оно включено.

### Медицинская хронология

- Новые записи сверху.
- Группировка по месяцу или году.
- Иконка и подпись обозначают тип события.
- Вложения показываются как файлы с типом, размером и состоянием загрузки.

### Календарь здоровья

- Календарь находится на главной и объединяет события всех питомцев.
- Дни обозначаются цветными точками без числовых счётчиков.
- Цвет точки кодирует тип: зелёный — вакцинация, фиолетовый — приём врача, синий — анализ, оранжевый — процедура или операция.
- На одной дате отображается не более одной точки каждого типа.
- Под календарём находится компактная легенда.
- Выбор даты раскрывает краткий список событий с аватаром и именем питомца.

### Нижняя навигация

- Четыре пункта: Главная, Питомцы, Клиники, Профиль.
- Высота вместе с внутренними отступами не более `80 px` без safe area.
- Выбранный пункт использует лаймовую подложку и заполненную иконку.
- Неактивные пункты используют контурные иконки.
- Текстовые подписи остаются видимыми.

## 10. Состояния интерфейса

### Загрузка

- Скелетон повторяет форму будущего контента.
- Не использовать полноэкранный spinner, если структура экрана уже известна.
- Фотография резервирует место до загрузки.

### Пустое состояние

- Объясняет, чего пока нет.
- Даёт одно понятное действие.
- Может использовать одну иллюстрацию Сени.

### Ошибка

- Называет проблему простым языком.
- Не обвиняет пользователя.
- Предлагает повторить действие или сохранить данные локально.
- Технические детали не показываются в основном тексте.

### Офлайн

- Ранее загруженные данные остаются доступными для чтения.
- Несинхронизированные изменения имеют текстовый статус.
- Возврат сети запускает повторную синхронизацию без потери введённых данных.

## 11. Движение

Движение объясняет изменение состояния, а не украшает экран.

| Сценарий | Длительность | Характер |
|---|---:|---|
| Нажатие кнопки | `100-140 ms` | Лёгкое сжатие |
| Переход состояния | `180-240 ms` | Ease out |
| Открытие листа | `240-320 ms` | Нативная пружина |
| Смена питомца свайпом | По жесту | Scroll snap |

Правила:

- Анимируются только `transform` и `opacity`.
- Нет бесконечных пульсаций и декоративных marquee.
- `prefers-reduced-motion` отключает необязательное движение.
- Завершение лекарства или задачи подтверждается изменением состояния, а не конфетти.

## 12. Голос интерфейса

### Тон

- Спокойный.
- Конкретный.
- Без медицинских выводов.
- Без инфантилизации владельца.
- Без тревожных формулировок там, где достаточно факта.

### Примеры

| Вместо | Используем |
|---|---|
| «С питомцем всё отлично!» | «Нет срочных задач» |
| «Ой, что-то пошло не так» | «Не удалось сохранить событие» |
| «Пора спасать здоровье питомца» | «Прививка запланирована на 24 сентября» |
| «Малыш ждёт таблеточку» | «Ветмедин, 1/2 таблетки в 20:00» |

### Формат данных

- Дата: `24 сентября 2026`.
- Время: `20:00`.
- Вес: `4,8 кг`.
- Дозировка: `1/2 таблетки` или точное значение из назначения.
- Не использовать относительные формулировки без абсолютной даты в деталях события.

## 13. Доступность

- Контраст основного текста: не менее `4.5:1`.
- Контраст крупного текста и иконок: не менее `3:1`.
- Зона нажатия: минимум `44 x 44 px`.
- Интерфейс работает при увеличении текста до `200%`.
- Статус не передаётся только цветом.
- Фотографии получают осмысленный alt-текст.
- Декоративные изображения скрываются от screen reader.
- Focus state видим на клавиатурной навигации.
- Все действия доступны без точного жеста свайпа.

Проверенные сочетания светлой темы:

| Сочетание | Контраст |
|---|---:|
| `color.ink` на `color.lime` | `14.34:1` |
| `color.ink` на `color.sky` | `7.92:1` |
| `color.ink` на `color.coral` | `6.59:1` |
| `color.inkMuted` на `color.bg` | `5.50:1` |

## 14. Что не делаем

- Не превращаем продукт в социальную сеть о питомцах.
- Не используем больничную стерильность как главный стиль.
- Не делаем все блоки карточками.
- Не используем фиолетово-синие AI-градиенты.
- Не добавляем декоративные медицинские показатели.
- Не показываем фальшивую точность или выдуманные данные.
- Не смешиваем несколько наборов иконок.
- Не используем случайные эмодзи.
- Не добавляем glassmorphism на каждую поверхность.
- Не используем милый тон в ошибках, приватности и медицинских событиях.

## 15. Решения для согласования

### 1. Характер

Рекомендация: утвердить направление **«спокойная забота»**. Оно балансирует медицинскую надёжность и личный характер продукта.

Альтернатива: более клинический стиль. Он повысит ощущение строгости, но сделает продукт холоднее и менее отличимым от приложений клиник.

### 2. Главный цвет действия

Рекомендация: оставить лаймовый для главного действия и выбранной навигации. Голубой остаётся брендовым фоном.

Альтернатива: голубой как цвет кнопок. Это будет привычнее, но снизит уникальность палитры.

### 3. Присутствие Сени

Рекомендация: логотип, onboarding, пустые состояния и одна редкая деталь в навигации. Не использовать маскота в медицинских карточках.
