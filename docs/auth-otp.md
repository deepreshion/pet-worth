# Вход по Email OTP

## Приложение

Экран входа запрашивает письмо через `signInWithOtp` и показывает поле из 6 разрядов. Один native TextInput поддерживает вставку, системное автозаполнение и VoiceOver. Вход подтверждается кнопкой через `verifyOtp({ email, token, type: "email" })`; сессия обрабатывается общим AuthProvider.

Повторная отправка доступна через 60 секунд. Таймер основан на времени, поэтому уход приложения в фон не продлевает ожидание. Смена почты сохраняет введённый адрес и сбрасывает код; возвращение к прежнему адресу не обходит таймер. Кнопки блокируются на время запроса. Ошибки сети, лимита отправки, неверного/просроченного кода показываются на RU/EN. Обработчик ранее отправленных magic links сохранён.

## Облачный проект: Resend SMTP, тестовый режим

Настроено 3 ноября 2026 в проекте `jpqrpdbhzrjzkeehtwnj`:

- Custom SMTP включён: `smtp.resend.com`, порт `465`, username `resend`.
- Отправитель: `Pet Worth <onboarding@resend.dev>`.
- Ключ Resend пользователь внёс непосредственно в Supabase; секрет не хранится в репозитории и не передаётся приложению.
- В **Magic link or OTP** и **Confirm sign up** сохранён минимальный HTML из `supabase/templates/email-otp.html` с `{{ .Token }}`. Тема обоих писем: `Pet Worth — код для входа / sign-in code`.
- Email provider и Confirm email включены, длина OTP — **6 цифр**, срок — **3600 секунд**. Длина изменена с 8 до 6 цифр 3 ноября 2026 по просьбе пользователя; срок кода не менялся.

Через настоящий `supabase.auth.signInWithOtp` запрошены тестовые письма на почту аккаунта Resend. Supabase вернул успешные ответы, Resend показал **Delivered**. После изменения длины в новом доставленном письме проверено наличие ровно **6 цифр**, без вывода кода в отчёт. Ввод полученного кода и создание новой сессии в приложении в этой проверке не выполнялись; существующая сессия симулятора сохранена.

**Ограничение:** у Resend пока нет подтверждённого домена. `onboarding@resend.dev` разрешает отправку только на email владельца аккаунта Resend. Для входа других пользователей нужно подтвердить свой домен в Resend и сменить Sender email address в Supabase на адрес этого домена. До этого отправка другим пользователям не готова к выпуску.

Интервал повторной отправки в интерфейсе — 60 секунд. Помимо ограничений Resend действуют серверные лимиты Supabase; форма SMTP указывает базовый лимит 30 писем/час после подключения custom SMTP. Секрет SMTP менять только через Dashboard.

## Локальный Supabase

В `supabase/config.toml` включено подтверждение email, настроены `otp_length = 6`, `otp_expiry = 3600`, `max_frequency = "1m"`, и подключены минимальные шаблоны `magic_link` и `confirmation`. Это локальная настройка; изменение файла не применяет её в облаке. Если стек уже запущен, нужен перезапуск без сброса базы.

Smoke-сценарий описан в `e2e/README.md`: запрашивает письмо в приложении, читает одноразовый код из локального mailbox и вводит его через Maestro. Только локальные тестовые аккаунты. Docker daemon в текущем окружении недоступен, поэтому полный E2E с реальным локальным Supabase пока не выполнен.
